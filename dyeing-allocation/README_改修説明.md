# 染色窯割り当て管理システム ― コードレビューと高速化（v2）

対象ファイル：`Dyeing_Allocation_Full.xlsm`（標準モジュール `Module1`）。添付の `DyeingAllocation.bas` もほぼ同じ内容です。
成果物：`DyeingAllocation.bas`（入れ替え用の完全版モジュール）

---

## ① 現状コードの分析

### 1-1. 処理が重い原因（実データ164件・14台・20列で見積もり）

| # | 箇所 | 内容 | 1回のREFRESHでのExcel呼び出し回数（概算） |
|---|---|---|---|
| A | `RefreshBoard` の並べ替えループ | 窯（14台）×スロット×全行（164行）を何度も走査。その中で `D.Cells(r,2)` を読み、さらに `MachineName()` で BoardMap のセルを読む。並べ替えのたびに、セルを1つずつ読み直している。 | **約60,000回のセル読み取り** |
| B | `DrawCard` ×164枚 | 1枚につき結合12回、罫線27プロパティ、フォント・配置・ShrinkToFit・値の書き込みなどで約150回の書式操作。とくに **Merge と Borders が重い**。 | **約25,000回の書式操作** |
| C | `CountDisplaySlots` | Bと同じく、14台×全行をセル単位で読む。 | 約5,000回 |
| D | 再描画の範囲 | LEFT/RIGHT/GRAY RECEIVED のように **カード1〜2枚しか変わらない操作でも、全カードを消して描き直す**。 | 上記を毎回 |
| E | 自動計算・イベント | `Calculation` と `EnableEvents` を止めていない（Data には `=SUM()` の数式があり、Editor にも数式がある）。 | 小〜中 |

**結論**：一番大きいのは B（セル結合と罫線の繰り返し）と、それを **毎回全カードに対して行う構造（D）** です。2番目が A（セルを1つずつ読む O(窯×スロット×行) のループ）です。`ScreenUpdating=False` はすでに入っているので、それだけでは速くなりません。

### 1-2. データ不整合・バグ（速度とは別に重要）

| 重要度 | 問題 | 詳細 |
|---|---|---|
| **致命的** | **状態セル BoardMap!O2:O3 が、自動拡張するマップ領域と重なっている** | マップは `BoardMap!B2:(slots+1)15` です。O列は「QUEUE 14」の列にあたります。今は20列なので、REFRESH のたびに `ClearContents` で **O2（モード）と O3（列数）が消え**、そこにカードIDが書き込まれます。<br>・**FILTER を押した直後に O2 の "FILTER" が消える** → 絞り込み表示のまま LEFT/RIGHT/COMPLETE が実行できてしまう（仕様違反）。さらに、絞り込み後の「見かけ上の隣」と Queue を入れ替えてしまう。<br>・600-AT が14件以上になると、O3 に **Batch ID が入り、それが「列数」として扱われる** → 消去範囲が数百列に膨らむ（極端に遅くなる／列数オーバーでエラー）。 |
| 高 | 窯名の大文字小文字・空白の扱いが不統一 | `ValidMachine` は大文字小文字を区別しない。一方 `RefreshBoard`・`MaxQueue`・`RenumberMachine` は完全一致で比較している。CHANGE MACHINE で `swing m/c` と入力すると保存は通るが、**そのBatchがボードから消える**（Dataには残る）。 |
| 中 | ADD 後にもう一度 SAVE を押すと二重登録 | Editor が ADD モードのまま残るため。現在 Batch No が全件空欄なので、重複警告も役に立たない。 |
| 中 | 保存処理が途中で失敗すると、半端な行が残る | ID・Machine・Queue を書いた後に検証や変換でエラーが出ると、それだけの行が残る。 |
| 中 | `RenumberMachine` が一時的に負の Queue を書き込む | 途中でエラーが起きると、負の値が残る。 |
| 中 | Queue に重複・欠番があると LEFT/RIGHT が効かない | 同じ値同士を入れ替えても何も変わらない。 |
| 低 | `CStr(エラー値)` で落ちる | Data に `#N/A` などがあると型不一致エラーになる。 |
| 低 | `"1/2"` のような文字列が日付に化ける | カードへ `.Value = CStr(...)` で書き込むと、Excel が日付として解釈することがある。 |
| 低 | ADD の書き込み行が A列だけで決まる | A列が空で他の列にデータがある行を上書きするおそれがある。 |

### 1-3. 結合セル（エラー1004）の残存調査

* Editor の結合範囲は `A1:E1, B5:D5 … B20:D20, A24:E24` です。ブック内の `Module1` には修正済みのループが入っていますが、**添付の .bas は修正前の版** でした。
* v2 では、Editor の読み書き・消去を **すべて `MergeArea` 経由** に統一しました（`EdVal` / `SetEd` / `ClearEd`）。結合の形が変わってもエラーになりません。
* ボード側は、描画前に必ず `UnMerge` してから貼り付けるため、1004 が起きる経路はありません。

## ② 改善案の比較

| 案 | 内容 | 効果 | 難易度 | リスク |
|---|---|---|---|---|
| 1. 設定の制御だけ | `Calculation`・`EnableEvents` の制御を追加 | 小（1〜2割） | 低 | 低 |
| 2. 配列での一括読み込み | Data を1回で配列に読み、並べ替えをメモリ上で行う | 中（Aが消える） | 低 | 低 |
| 3. **カードテンプレートのコピー** | 書式済みの空カードを1枚作り、`Copy` で貼り付けてから値を1回で書き込む | **大（Bが 約150回/枚 → 約3回/枚）** | 中 | 低（見た目は同じ） |
| 4. **差分再描画** | 変更前後の BoardMap を比べ、変わったカードだけ描き直す | **大（LEFT/RIGHT は2枚、GRAY は1枚だけ）** | 中 | 中 → 位置の正本を Data に一本化して対処 |
| 5. 結合セルの廃止 | 「選択範囲内で中央」などに置き換える | 中 | 中 | **レイアウトが変わる** |
| 6. Shape 方式や UserForm 化 | 描画方式そのものを作り直す | 大 | 高 | 高 |

**判断**：簡単な最適化（案1・2）だけでは不十分です。主な原因は「描画方法」と「毎回の全件再描画」なので、**描画処理の設計変更（案3＋4）が必要** です。ただし、シート構成・Dataの列・カードの見た目・ボタンは変えずに済む範囲にとどめました。案5・6は見た目や運用が変わるので採用していません。

v2 での各操作のExcel呼び出し回数（概算）：
* REFRESH／FILTER：約 90,000回 → **約 600回**
* LEFT／RIGHT・GRAY RECEIVED：全件再描画 → **カード1〜2枚と BoardMap の更新だけ**（約15回）
* COMPLETE／CHANGE MACHINE／SAVE：**その窯の、位置がずれたカードだけ**（列数が変わるときだけ全件再描画）

## ③ 修正版の主な変更点（`DyeingAllocation.bas`）

* **高速化**
  * Data を `Range.Value` で1回だけ読み込み、窯ごとの並び順（Queue → ID の順）をメモリ上で作成。
  * 空のカードテンプレートを `BoardMap!A22:C33` に自動生成し、1枚ごとに `Copy` してから値を12×3の配列で1回で書き込む。
  * 変更前後の BoardMap を比べ、位置・内容が変わったカードだけ描き直す（差分再描画）。
  * `ScreenUpdating`・`EnableEvents`・`Calculation` を処理中だけ止め、**エラーが起きても必ず元に戻す**（全ボタン共通の `FastOn` / `Finish`）。万一の復旧用に `ResetExcelSettings` マクロも用意。
* **整合性**
  * 状態セルを **`BoardMap!B18`（モード）と `B19`（描画済み列数）** に移動し、マップと重ならないようにした（O2/O3 は使わない）。
  * 窯名の比較を「前後の空白を除き、大文字小文字を区別しない」に統一。保存時は BoardMap の正式な表記で書き込む。
  * LEFT/RIGHT の前に、その窯の Queue を 1..n に正規化（重複・欠番があっても正しく動く）。Data には **変わったセルだけ** を書き込む。
  * 操作対象は「選択したカードのID」から Data 上の現在位置を検索して決める。Data が直接編集されていてボードと食い違う場合は、自動で REFRESH して「もう一度選択してください」と表示する。
  * ADD は全項目を検証してから **1行を1回で書き込む**。保存後は Editor を EDIT モード（新しいID）に切り替え、二重登録を防ぐ。
  * ID の重複、未登録の窯名、ID のない行は A5 に警告を表示する（データは変更しない）。
  * 絞り込み中は SAVE も禁止（従来は SAVE だけ素通りしていた）。
* **使いやすさ**
  * LEFT/RIGHT・GRAY RECEIVED・EDIT/CHANGE MACHINE の後は、**移動後のカードを選択したままにする**（続けて LEFT を押せる）。
  * CHANGE MACHINE で番号（1〜14）でも窯を指定できるようにした（一覧を表示）。
  * COMPLETE の確認メッセージに 窯／Queue／PO／Color／Batch No を表示する（現在 Batch No が空のため）。

**表示上の小さな変化**
* 合計重量は Kg1〜Kg3 の合計から計算します（仕様どおり。現在のデータは全件 Total Kg 列と一致することを確認済みです）。
* ボードのカードには日付を日付型（書式 `yyyy/mm/dd`）で表示します。
* `1/2` などが日付に化けないよう、文字として表示します。
* 書式 `#,##0.##"kg"` は従来どおりなので、`1,000.kg` のように末尾に「.」が付く表示も同じです。気になる場合は `#,##0.##` を `#,##0.0#` などに変えられます。

## ④ 更新手順（初心者向け）

### 事前準備
1. Excelを閉じた状態で、**`Dyeing_Allocation_Full.xlsm` をコピーしてバックアップ** を作ります（例：`Dyeing_Allocation_Full_backup_20261116.xlsm`）。
2. 元のブックを開き、「コンテンツの有効化」を押します。

### 古いモジュールの削除
3. `Alt + F11` で VBA エディタを開きます。
4. 左の「プロジェクト」ウィンドウで `VBAProject (Dyeing_Allocation_Full.xlsm)` → `標準モジュール` を開きます。
5. `Module1` を右クリック →「Module1 の解放」→「エクスポートしますか？」には **「はい」**（予備として保存）を選びます。
   ※ `DyeingAllocation` という名前のモジュールもある場合は、同じ手順で削除してください。**同じ名前のマクロが2つあるとコンパイルエラーになります。**
   ※ `Sheet1`〜`Sheet5` と `ThisWorkbook` は消さないでください（中身は空です）。

### 新しいモジュールのインポート
6. メニューの「ファイル」→「ファイルのインポート」で `DyeingAllocation.bas` を選びます。
7. 「標準モジュール」の下に `DyeingAllocation` が追加されたことを確認します。
8. メニューの「デバッグ」→「VBAProject のコンパイル」を実行し、エラーが出ないことを確認します。
9. `Ctrl + S` で保存し（形式は .xlsm のまま）、VBA エディタを閉じます。

### 初期設定は必要？
* **SetupBoard の実行は不要です。** ボタンはマクロ名（`MoveLeft` など）で登録されており、名前は変えていません。
* 最初に **REFRESH を1回押してください。** 状態セル（BoardMap!A17:B19）とカードテンプレート（BoardMap!A21:C33）が自動で作られ、ボード全体が描き直されます。
* Data シートは **一切消去しません**。REFRESH は読み込みだけで、Data を変更しません。

### 動作テスト（バックアップのコピーで行うのがおすすめ）
| # | 操作 | 確認すること |
|---|---|---|
| 1 | REFRESH | 164件が従来と同じ位置・見た目で表示される／A5 が「MODE: ALL ACTIVE … (20 queue columns)」になる |
| 2 | カードを選んで RIGHT を3回 | 毎回すぐ動き、選択がカードについていく／Data の Queue が入れ替わり、重複がない |
| 3 | LEFT で元に戻す → REFRESH | 位置が変わらない（差分描画と全件描画の結果が一致する） |
| 4 | GRAY RECEIVED | 背景色が `#B7DEE8` と白で切り替わり、最下段の文言も変わる |
| 5 | CHANGE MACHINE で `14` と入力 | Swing M/C の末尾に移り、元の窯の Queue が 1..n に詰まる |
| 6 | ADD → 入力 → SAVE BATCH → もう一度 SAVE | 新規行が1行だけ追加される（2回目は同じ行の更新になる） |
| 7 | EDIT → Kg を変更 → SAVE | カードの合計重量が更新される |
| 8 | COMPLETE | カードが消え、Data の Status=Completed、Completed At に日時が入る |
| 9 | U3/X3 を設定して FILTER | 指定日のBatchだけが左詰めで表示される／**LEFT/RIGHT/ADD/EDIT/COMPLETE/SAVE が拒否される**／Data の Queue が変わらない |
| 10 | CLEAR FILTER | 全件表示に戻る |
| 11 | Data の Machine を一時的に `xxx` にして REFRESH | A5 に未登録窯名の警告が出る（確認後は元に戻す） |

**元に戻したいとき**：バックアップのブックを使うか、`DyeingAllocation` を削除して、手順5でエクスポートした `Module1.bas` をインポートし直してください。

## 補足：今回は採用せず、提案にとどめるもの
* Batch No が全件空欄なのに、SAVE では必須になっています。既存のカードを EDIT すると、必ず Batch No を入力させられます。運用に合わせて、必須をやめる（重複チェックだけにする）ことを検討してください。
* 窯が増減する場合は、`MACHINE_COUNT` と Allocation 左側の窯名ブロックを同時に変更する必要があります。BoardMap!A2:A15 が窯名の正本です。
